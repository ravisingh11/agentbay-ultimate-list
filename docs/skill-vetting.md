# How AgentBay vets skills

[Back to the catalogue](../README.md) · [Find a skill on AgentBay.io](https://agentbay.io/)

I look for skills with a source you can trace, instructions you can inspect and
a clear job they can do. AgentBay makes those checks visible so you can decide
what belongs in your project.

| Check | What we look at |
| --- | --- |
| Source and publisher | A public, active repository and a traceable source link. The [provider registry](providers.md) records verified GitHub owners. |
| Instructions | Where a listing points to a skill file, inspect the pinned `SKILL.md`. For deeper reviews, record its scope, tools, account access and limits. Check relevant companion files when a skill depends on them. |
| Tested examples | [AgentBay walkthroughs](https://agentbay.io/skills/workflows/) record the exact revision, agent, task, output and checks. Evidence belongs to that revision and run. |
| Fit for your project | Read the publisher’s requirements and check the tools, permissions and environment before installing. |

## Website finder and GitHub catalogue

The website finder verifies pinned instruction files and deduplicates
identical Git blobs. Official provider sources qualify without popularity
minimums. Community finder sources need at least **5,000 stars or 2,000 forks**.
All finder repositories must pass the public, active and recent-evidence checks.

This public list also includes repositories, collections and tools. Its reviewed
curation and imports preserve listing IDs, corrections and exclusions. A
repository-level listing is a lead to inspect. Follow the actual skill file and
the publisher’s license before installing or redistributing it.

The [repository guardrails](guardrails.md) cover changes to this catalogue.
For a third-party skill, use the linked source and the evidence for that
specific skill. Publisher ownership, instruction review and tested use are
separate checks.
