# Data reference

[Home](../README.md) · [Contribution workflow](../CONTRIBUTING.md)

The combined [`catalog.json`](../catalog.json) is a UTF-8 JSON array. [`catalog.csv`](../catalog.csv) has the same fields and row order. The skills and projects downloads are disjoint partitions of those complete records; different skills may share a repository.

| Field | Type | Meaning |
| --- | --- | --- |
| `id` | string | Stable catalogue identifier; local additions use `community:` plus a UUID. |
| `name` | string | Recorded component or project name. |
| `description` | string | Original metadata summary generated by the documented summary policy. |
| `type` | string | Listing type; types beginning with “skill” enter the skills subset. |
| `website_url` | string | Public documentation, project page or component source URL; may be empty. |
| `repository_url` | string | Public GitHub repository containing the listed component. |
| `categories` | string array | All recorded categories; the first nonempty value selects the browsing category. |
| `tags` | string array | Frameworks, technologies and other source labels. |
| `use_cases` | string array | Original topic-based prompts generated from structured metadata. |
| `license` | string | Reported upstream license; empty means unknown. |
| `license_scope` | string | What the upstream license observation describes, when recorded. |
| `listing_scope` | string | Originating catalogue classification, such as `direct_list`, `raw_inventory` or `community`. |
| `repository_archived` | boolean | Archive status at the recorded observation; absence from a later import does not update this automatically. |
| `repository_status_checked_at` | ISO timestamp or null | Time of recorded repository-status evidence. |
| `agentbay_url` | string | Public AgentBay listing link, or empty for an independent addition not yet on the website. |
| `github_stars` | nonnegative integer or null | Cached repository star count, shared by components in that repository. |
| `github_stars_checked_at` | ISO timestamp or null | Observation time of the cached count. |
| `recommended` | boolean | Deprecated compatibility field; always false. |
| `preferred_provider` | string | Verified official publisher from the owner registry, or empty. |

CSV arrays are JSON-encoded inside cells. Booleans are `true`/`false`; nulls are empty CSV cells. For example, parse a categories cell with `json.loads(row['categories'])` in Python. JSON remains the unambiguous representation of null versus empty text.

## Identity and duplicate handling

IDs identify listings, not repositories. Two skills in different paths stay separate, and a repository-level listing may coexist with its component listings. Only records with the same normalized repository, website source, name and type are consolidated. Their categories and tags are combined; a retained ID remains stable. Older IDs map to it in [`provenance/aliases.json`](../provenance/aliases.json).

The map is flattened so a consumer can resolve an older ID in one lookup. A reviewed exclusion may retire a retained ID; consult `data/curation.json` for deliberate exclusions. Do not use names as unique keys or assume a repository appears only once.

## Source and limits

[`sync-manifest.json`](../sync-manifest.json) records AgentBay source hashes, the last successful import mode/time, curation input hashes, counts and hashes for generated files. `live_api` means public live curation APIs were read; `packaged_snapshot` means only deployed static snapshots were used. Neither mode is a fresh audit of every linked GitHub project. Website recommendations and curation are not mirrored here: `recommended` remains false, and rankings, favorites, notes and personal collections are outside the export contract. Maintainer imports can augment listing facts; reviewed repository curation is applied separately.

[`provenance/descriptions.json`](../provenance/descriptions.json) records the versioned summary method and per-record fingerprints. Publisher description and use-case prose are excluded from its inputs. A metadata summary may lack a specific capability description; that limitation is recorded rather than guessed.

The full catalogue and website finder have different purposes and counts. The finder indexes verified instruction files under its source-eligibility rules. This list also contains projects, tools, repositories and collections. Official attribution verifies owner identity, not quality, security or compatibility.

See [LICENSING.md](../LICENSING.md) before reusing linked third-party material. This list's MIT license does not change upstream licenses.

Maintenance PR reports are supporting public evidence, not a new catalogue schema or an endorsement. A stable `community:` ID identifies a proposed individual skill across repeated runs. Source paths are compared independently of upstream commit changes, and explicit exclusions remain effective. The finder snapshot hash identifies the inspected feed; each proposed addition separately verifies its pinned publisher bytes. Candidate-provider reports never set official attribution by themselves.
