# Maintaining the list

AgentBay is the primary source and maintainer. This repository publishes a curated, reusable list; it does not ship the website's application code or account data. Website presentation changes do not trigger a catalogue change. Relevant source additions and factual corrections enrich the list through a reviewed import.

## Repository layout

The root README and category pages are generated by `scripts/catalog.py`; edit its renderer and regenerate rather than hand-editing those pages. The only maintained installer instructions are `skills/agentbay-skill-installer/SKILL.md`; downloads and website publication derive from that file.

Upstream names such as `legacy-catalog.json` and `legacySavedOnly` are active compatibility contracts. The importer still uses them to preserve supported projects and exclude saved-only records. Do not remove those checks as cosmetic cleanup.

## Render a reviewed local change

```sh
python3 scripts/catalog.py render
python3 scripts/catalog.py check
python3 -m unittest discover -s tests -v
```

Rendering uses the accepted catalogue plus maintained curation. It makes no network requests and does not change the import timestamp. Repeating it without input changes produces identical bytes. Direct changes to baseline exports are rejected; use the curation file instead.

Descriptions and use cases are regenerated under the original-summary policy. All six exports, the browsing pages, aliases, provenance and manifest update together. Writes refuse symlinked targets, unowned output files and unexpected output paths. Only obsolete pages recorded as generated and still bearing their generated marker can be removed.

## Import catalogue updates from AgentBay

Python 3.9+ and curl are required; no website checkout, credentials or third-party Python packages are needed:

```sh
python3 scripts/catalog.py refresh
python3 scripts/catalog.py check
python3 -m unittest discover -s tests -v
```

Refresh reads AgentBay's published catalogue, enrichment, repository metadata and curation endpoints. It adds new IDs, updates existing upstream metadata, preserves accepted IDs absent from the import, then reapplies reviewed repository curation. Known duplicates resolve to their retained IDs. The manifest records source hashes and the add/update/retention counts. Review the diff before committing.

Upstream absence is not an automatic removal. A maintainer reviews a dead link, archive state, rights request or other reason and records an explicit exclusion in `data/curation.json`. Likewise, an upstream metadata update cannot erase a correction recorded here. A contribution does not automatically publish to the AgentBay website; maintainers can separately adopt it there.

If live APIs are unavailable, ordinary refresh fails before writing. A maintainer can deliberately choose the deployed static snapshots:

```sh
python3 scripts/catalog.py refresh --snapshot
```

The manifest identifies this as `packaged_snapshot`; it is not a claim of live API parity. Retry the ordinary refresh when the APIs recover. Do not use a source failure or an empty response as permission to replace the catalogue with an empty list.

For an AgentBay maintainer verifying a deployment against a local website checkout, the optional command is:

```sh
python3 scripts/catalog.py refresh --site-source /path/to/agentbay/public
```

This verifies every fetched static source against its local bytes. A mismatch fails before output changes. It does not import application code. The website deployment helper may invoke this command when this data repository exists at its configured local path.

## Review and publish

Use a focused branch and pull request for imports and curation changes. Review counts, exclusions, alias changes, sources and generated output. Check that no private data, copied publisher prose or unsupported claims have entered the list. CI validates the same offline outputs as contributors can reproduce locally.

AI Software Toolkit manages the checks and review workflow around these catalogue data commits. Proof evaluates the configured evidence, while catalogue validation checks consistency across generated outputs. Maintainers authorize acceptance, merge and publication separately; see the [guardrails](guardrails.md).

Only maintainers change the owner registry or summary policy. Update the policy version when summary behavior changes and regenerate its provenance. Preserve the stable export fields; document and version any intentional schema change before consumers rely on it.

Repository visibility is a separate publication decision. Preparing or pushing a review branch does not itself make a private repository public. Before changing visibility, review the complete reachable Git history as well as the source tree, confirm the license scope and contribution documentation, and verify checks against the exact source revision.

Follow the [public-release procedure](public-release.md) for checks on the approved revision, real GitHub installation, checksum-verified public/private context retrieval and the checks that can only be completed after an explicit visibility change.

Keep execution traces and temporary validation projects outside the checkout. Current installer checks and app verification gaps are summarized in [installer verification](installer-validation.md).

See [the guardrails page](guardrails.md) for advisory checks, actual producer commands, external-review boundaries and current GitHub enforcement limits.
