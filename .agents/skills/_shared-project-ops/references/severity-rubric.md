# Severity Rubric

- `critical`: active exploitability, data loss, auth bypass, payment risk, or release-blocking failure
- `high`: user-visible broken flow, strong security weakness, persistent data corruption, or high-likelihood production failure
- `medium`: important bug, missing coverage on risky path, doc error that can mislead operators, or moderate reliability issue
- `low`: maintenance issue, minor inconsistency, low-impact edge case, or non-blocking documentation drift

Choose severity by impact and confidence, not by code smell alone.
